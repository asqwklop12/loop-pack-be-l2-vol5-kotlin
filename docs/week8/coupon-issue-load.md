# 쿠폰 발급 100 VU — 한도를 넘겨 발급된다

## 조건

- 2026-11-08, 로컬 `commerce-api` (`local` 프로필), 로컬 MySQL
- 캠페인 2, 총 발급 한도 119, 시작 전 발급 수 0, 쿠폰 0장
- k6 `shared-iterations`, 100 VU, 1000회. 회차마다 다른 사용자(`X-USER-ID` 100000~100999)

```
CAMPAIGN_ID=2 k6 run docs/week8/k6-coupon-issue.js
```

## 결과

| 항목                    | 값                               |
| ----------------------- | -------------------------------- |
| 응답                    | 201 1000건, 200·400·그 외 0건    |
| `coupon` 행             | 1000 (사용자 1000명)             |
| 캠페인 `issued_count`   | 26                               |
| 지연                    | 평균 206ms, p95 360ms, p99 392ms |

한도 119 인데 쿠폰은 1000장 나갔다. 1000명이 한 장씩 가져갔고, 캠페인의 발급 수는 1000 이 아니라 26 으로 남았다.

## 왜

발급 수 증가가 읽고 +1 해서 쓰는 방식이고 락이 없다. 동시에 들어온 요청들이 같은 `issued_count` 를 읽고 각자 덮어써서
974번의 증가가 사라졌다. 발급 수가 계속 한도 아래로 보이니 품절 검사가 한 번도 걸리지 않았다.

쿠폰 행은 `(campaign_id, user_id)` 유니크 키로 사용자당 한 장만 막는다. 서로 다른 사용자 사이의 총량은 막지 못한다.
